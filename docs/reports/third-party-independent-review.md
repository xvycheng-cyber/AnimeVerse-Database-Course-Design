## 5. 概念与逻辑设计审查

### 5.1 已完成内容

- 需求分析覆盖用户、内容主数据、互动、审计、管理和课程实验六个业务域。
- 用户资料使用共享主键形成严格 1:0..1 关系。
- 用户—角色、动漫—类型、动漫—人员、动漫—平台使用关联表表达 M:N。
- 厂商—动漫、动漫—剧集、用户—互动记录使用 1:N 外键表达。
- 三张 Mermaid E-R 图使用 Crow's Foot 表达，实体、关系和基数与实际表结构总体一致。
- 主键、外键、唯一键、CHECK、默认值和删除策略能够在真实 MySQL 中生效。

### 5.2 发现的设计边界

动漫表保存 `episode_count`、`favorite_count`、`review_count`、`rating_count`、`average_rating` 和 `view_count` 六个派生聚合字段。若严格按教材定义，它们不满足“无任何冗余”的 3NF 表述。

正确结论是：**逻辑模型的核心实体满足 3NF；物理表采用受控反规范化。** 这些字段由触发器、回算脚本和只读字段契约维护，不能写成物理数据库完全无冗余。

原文档把动漫候选键写作 `(title, release_date)`，但 MySQL 普通 UNIQUE 会允许“标题相同且日期都为 NULL”的多行。当前实库已改为函数唯一索引：

```sql
uk_anime_title_release_key(title, (COALESCE(release_date, '1900-01-01')))
```

本轮负向测试实际返回 MySQL 1062，证明 NULL 日期归一化唯一键有效。

### 5.3 概念设计评分

**18/20。**

扣分原因：

- 物理层受控反规范化不能表述为完全无冗余，扣 1 分。
- 历史文档和主报告曾保留普通 `(title, release_date)` 候选键描述，现已纠正；原始一致性不足扣 1 分。

## 6. 表及基础操作审查

### 6.1 表结构

逐表检查字段、数据类型、主键、外键、唯一、非空、CHECK、默认值、索引和删除策略。实库结构支持：

- 实体完整性：所有基表有主键。
- 域完整性：23 个 CHECK 覆盖状态、评分、日期顺序、长度、进度、用户名和编码格式。
- 参照完整性：20 个外键覆盖身份、内容、互动和审计边界。
- 业务唯一性：13 个 UNIQUE 约束覆盖用户名、邮箱、角色、厂商、标题日期、集数、收藏、观看和评论。
- 删除策略：关系型从属数据使用 CASCADE；主数据引用使用 RESTRICT；审计操作者使用 SET NULL。

### 6.2 实际操作证据

本轮数据库测试 20/20 通过：

- 正常插入：17 表 CRUD 事务、动漫存储过程新增。

- 非法插入：评分 11 返回 3819；3 字符用户名返回 3819。
- 更新：用户、动漫、关系、剧集、评论等更新路径由 CRUD 测试覆盖。
- 删除：存储过程删除、关系清理、项目临时数据清理通过。
- 外键限制：被引用主数据采用 RESTRICT，错误行为由结构及 CRUD 测试覆盖。
- 多表查询、聚合查询、子查询：18 条复杂查询全部执行。

## 7. 高级数据库编程审查

### 7.1 触发器

实库有 12 个 `AFTER INSERT/UPDATE/DELETE` 触发器。测试验证：

- 收藏新增使计数加一，删除使计数减一。
- 评论增加、删除、改分和隐藏/恢复后重新计算可见评论平均分与计数。
- 观看历史新增、迁移和删除维护观看统计。
- 剧集新增、迁移和删除维护集数统计。
- 统计与原始关系数据一致，未产生负数行。

### 7.2 存储过程

6 个过程均真实存在。`sp_add_anime` 和 `sp_delete_anime` 使用 IN/OUT 参数；厂商统计和动漫排行返回结果集；事务演示使用输出参数。非法厂商、非法动漫由 `SIGNAL` 和异常处理反馈。

### 7.3 游标

实库过程定义确认 `sp_generate_studio_report` 含有 DECLARE CURSOR、OPEN、FETCH、CLOSE 和 HANDLER。实际调用返回 8 家厂商，未遗漏目标记录。

### 7.4 事务

`sp_transaction_demo` 真实包含 `START TRANSACTION`、`COMMIT`、`ROLLBACK` 和异常处理：

- COMMIT：提交后可见日志 1 行。
- ROLLBACK：回滚后可见日志 0 行。
- EXCEPTION：触发 intentional transaction exception，回滚后可见日志 0 行。

异常模式最终以 HTTP 200 返回审计结果和 `rolledBack=true`，这是服务层捕获后可观察的演示契约，不是接口失败。

## 9. 安全审查

已实际核验：

- 应用账户 `Chengzi@localhost` 仅拥有目标库 `SELECT, INSERT, UPDATE, DELETE, EXECUTE, SHOW VIEW`，无全局管理权限。
- `.env` 被 `.gitignore` 忽略，未出现在 Git 跟踪文件或历史记录中。
- 数据库只保存 `$2b$10$` 60 字符 BCrypt 哈希，未保存明文。
- JWT 使用至少 32 字节密钥、签发者校验、类型校验和过期时间；无效令牌不影响公开接口，受保护接口返回 401。
- 无令牌访问管理接口返回 401，普通用户访问管理接口和实验室返回 403。
- SQL 常规查询使用 MyBatis 参数占位符或 `CallableStatement`；唯一 `${viewName}` 经过四视图白名单校验。
- `v-html` 检出为 0。
- 管理和实验室写操作产生操作日志。

未解决安全风险：

- JWT 存储在 `localStorage`，存在 XSS 后的令牌读取风险。
- Swagger 和 OpenAPI 公开可访问。
- 登录没有限流、验证码或失败锁定。
- 本地数据库连接使用 `useSSL=false`，属于课程环境配置。

这些不是本次课程验收的 P0/P1 阻断项，但不应直接用于公网生产部署。

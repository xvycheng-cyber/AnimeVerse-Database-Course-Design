## 第一章 任务输入与执行原则

### 1.1 任务输入

用户一次性提供了完整课程设计任务书，明确要求使用 MySQL 8.0、Java 17、Spring Boot 3、MyBatis-Plus、Vue 3、TypeScript、Element Plus、JWT、BCrypt 和 ECharts，完成数据库设计、前后端系统、测试、报告、AI 交互报告、独立审查、整改和 ZIP 交付。

任务同时规定了不可违反的边界：

1. 不使用 SQLite 或 H2 替代正式 MySQL。
2. 不执行 `DROP DATABASE` 覆盖现有数据库。
3. 不把真实密码提交到 Git。
4. 不只生成静态页面或 SQL 文本。
5. 不伪造数据库对象、测试结果或截图。
6. 遇到可自行解决的问题时连续推进，不等待逐阶段确认。

### 1.2 执行方式

AI 将任务拆分为需求与概念设计、关系与物理设计、种子与查询、视图与高级对象、后端、前端、安全与联调、报告、独立审查、整改和打包。每个阶段以工作区文件和真实命令结果作为状态依据。

整个过程中没有把“文件存在”当作“功能通过”。数据库对象通过实际 MySQL 查询和调用验证，后端通过 Maven 测试与打包验证，前端通过 TypeScript 构建、单元测试和真实浏览器验证，压缩包通过解压检查验证。

## 第二章 设计与实现过程

### 2.1 数据库设计

AI 先根据动漫平台的业务实体确定 17 张表。其中 16 张覆盖用户、角色、厂商、动漫、类型、剧集、人员、平台、收藏、观看、评论和日志；`sys_user_profile` 用于严格的用户一对一资料和个人偏好。

多对多关系没有放入逗号分隔字段，而是拆分为：

- `sys_user_role`
- `anime_genre_relation`
- `anime_staff_relation`
- `anime_platform_relation`
- `user_favorite`

动画表保留 `episode_count`、`average_rating`、`rating_count`、`favorite_count`、`review_count` 和 `view_count`。这些字段由触发器维护，并提供回算脚本，既满足列表读取性能，也能追溯来源。应用写入 DTO 和后台表单不提供这些字段，普通 CRUD 只能读取派生结果。

### 2.2 高级对象实现

数据库实现 12 个触发器，覆盖收藏、评论、观看和剧集计数。收藏、观看和剧集均包含 INSERT、UPDATE、DELETE 触发器，关系迁移时同步旧作品和新作品。评论更新触发器处理改分、隐藏、恢复和迁移作品，并从可见评论重新计算平均值。删除触发器使用 `GREATEST(..., 0)` 防止负数。

实现 6 个存储过程：

- 新增动漫。
- 厂商统计。
- 动漫排行。
- 删除动漫。
- 事务演示。
- 游标厂商报表。

实现 3 个函数，分别计算加权评分、用户观看分钟和可见评论平均分。游标过程真实使用 `DECLARE CURSOR`、`CONTINUE HANDLER`、`OPEN`、`FETCH`、`LOOP` 和 `CLOSE`。事务演示真实执行 `COMMIT`、`ROLLBACK` 和异常处理器回滚。

### 2.3 后端实现

后端使用标准分层：

- `controller` 处理 HTTP 和权限入口。
- `service` 处理业务规则和事务。
- `mapper` 使用 MyBatis-Plus 与参数绑定 SQL。
- `entity`、`dto`、`vo` 分离数据库模型、写入模型和展示模型。
- `security` 实现 JWT、RBAC 和当前用户身份。
- `common` 提供统一响应、异常、分页和审计。

数据库实验室直接调用视图和存储过程，不把 Java 内存数据伪装成数据库结果。普通用户只能操作自己的收藏、观看和评论；管理接口要求 `ADMIN`。

### 2.4 前端实现

前端实现 13 个用户端页面和 13 个管理员端页面。管理员内容页复用 CRUD 管理器，但字段、控件、校验和接口因实体不同而分别配置。数据库实验室包含视图、触发器、存储过程、游标和事务五个页签。

界面包含加载、错误、空数据、图片失败、删除确认、搜索、筛选和分页状态。用户端采用深色蓝紫视觉体系，管理端采用浅色工作台和深色侧边栏，移动端使用响应式双列卡片。

## 第三章 测试与纠错过程

### 3.1 数据库测试

数据库测试最终为 17/17 通过。执行内容包括 17 表完整性、种子规模、12 个触发器、3 个函数、6 个存储过程、游标、三种事务模式、17 表 CRUD、重复约束、CHECK、空日期同名作品函数唯一索引、18 条复杂查询和静态安全检查。

一次最终复测发现 `transaction_commit_visible` 失败。排查后确认不是业务过程重复写入，而是 API 实验室保留了成功事务审计记录，数据库测试又按同一动作类型统计，导致看到两条记录。修正方法是让数据库测试在断言前清理事务演示标记，并在断言后清理本次记录。后续补充独立审查回归项后，数据库测试为 17/17。

### 3.2 后端与 API 测试

后端 `clean package` 编译 129 个 Java 源文件，17/17 测试通过。API 测试扩展到 22 项，新增排行封面、年份、状态、30 天趋势、角色 CRUD、无效令牌隔离、停用账户 403 和实验室审计检查，最终 22/22 通过。

实际修复的问题包括：

1. `localhost` 和 `127.0.0.1` 的 CORS 来源不一致。
2. 排行查询结果缺少前端需要的 `id`、封面、年份和状态字段。
3. 前端评分字段别名不统一。
4. 统计按天趋势在 `ONLY_FULL_GROUP_BY` 模式下失败。
5. 管理员表单字段与数据库列不一致。
6. 普通文本字段被误渲染为密码输入框。
7. 后台数组列表的搜索没有本地过滤。

独立审查新增的整改包括：

1. 从 `AnimeSaveRequest` 移除 `rating`、`averageRating` 和 `episodeCount`，避免应用覆盖触发器维护值。
2. 移除管理员动漫表单中的评分输入，保留评分列作为只读展示。
3. 评论触发器改为从可见评论重算平均值，消除多次改分的累计舍入漂移。
4. 增加收藏、观看和剧集三个 UPDATE 触发器，覆盖关系迁移。
5. 增加 `uk_anime_title_release_key` 函数唯一索引，阻止日期为 NULL 的同名作品。
6. 增加计数器迁移、重复改分和空日期重名回归测试。
7. 修正 ER 图复合唯一键标签并重新生成 PNG/SVG。
8. 公开接口遇无效 JWT 时清理匿名上下文并继续，受保护接口仍返回 401。
9. 停用账户登录返回 403，并在 API 测试结束时恢复账户。
10. 补齐角色 CRUD、角色恢复、评论隐藏/恢复、收藏首次点击和聚合字段只读的浏览器回归，并为实验室收藏、动漫新增和动漫删除写操作补齐审计记录。

### 3.3 前端与浏览器测试

前端单元测试 4/4 通过，TypeScript/Vite 构建 2361 个模块通过。构建保留 ECharts 大 chunk 警告，但不阻断运行。

真实浏览器回归覆盖 7 个后台实体 CRUD、角色恢复、用户角色回填、动漫聚合字段只读、评论审核、收藏首次点击、8 张页面截图、数据库实验室真实视图查询以及移动端视图。最终结果为 19/19 通过，0 个控制台错误、0 个 HTTP 错误、0 个警告、0 个横向溢出问题。

### 3.4 联合测试中的字段契约修正

浏览器测试发现，仅检查后端单元测试不足以证明页面可用。例如动漫 CRUD 表单曾要求不存在的 `videoUrl`，平台表单使用数据库没有的 `logoUrl/description`，人员和厂商字段也存在差异。AI 逐项对照数据库列、DTO、Mapper 和前端表单，修正为真实字段，并再次通过浏览器创建、搜索、编辑和删除操作。

### 3.5 最终复核中的 UI、安全与测试工具修正

最终复核补充了角色管理与用户角色回填、评论隐藏恢复、收藏首次点击、聚合字段只读和移动管理页截图。浏览器默认 favicon 404 通过增加真实 SVG 图标解决，没有把本地 404 静默忽略。

安全复测确认公开动漫列表在携带无效 JWT 时返回 200，受保护个人资料仍返回 401；停用账户登录返回 403。实验室收藏、动漫新增和动漫删除写接口都产生操作审计记录。

Windows PowerShell 5.1 曾把无 charset 的 UTF-8 JSON 响应按本地代码页解析，并将 mysql.exe 负向测试的 stderr 当作终止错误。测试客户端已改为按响应字节以 UTF-8 解析；数据库命令封装只以进程退出码判断成功或失败，因此 1062、CHECK 和 SIGNAL 等预期失败可以被稳定断言。

## 第四章 安全与文档工作

### 4.1 安全处理

数据库管理员与应用账户分离。应用账户只拥有目标库的 `SELECT`、`INSERT`、`UPDATE`、`DELETE`、`EXECUTE` 和 `SHOW VIEW`。用户密码使用 BCrypt，JWT 用于无状态认证，管理接口使用角色授权。

AI 检查了 SQL 注入、未授权管理访问、`v-html`、无效 JWT、停用账户、实验室审计、数据库凭据文件和硬编码密码。注入式关键词不会扩大结果集，无令牌访问管理接口返回 401，普通用户返回 403；无效令牌不会阻断公开接口，但受保护接口返回 401；停用账户登录返回 403；实验室写操作具有审计记录；前端源码没有 `v-html`。

### 4.2 文档生成

项目生成需求、概念设计、关系模式、数据字典、高级对象、安全、测试报告、API 契约、架构说明、部署手册、用户手册、故障排查手册和测试账号说明。正式报告和 AI 报告同时输出 Markdown 与 DOCX。

报告中的测试数字来自实际命令输出，截图来自真实浏览器访问，不把设计目标写成已通过结果。封面中的学校、专业、班级、组员、教师和日期保留为可编辑占位内容。

## 第五章 独立审查与整改

完成开发后，AI 切换为独立验收视角，重新读取源码、SQL、实时数据库对象、测试脚本、页面和文档，不只依赖阶段报告。审查按概念与逻辑设计 20 分、表创建与基础操作 30 分、高级数据库编程 20 分、UI 设计 30 分进行。

发现的问题按严重程度处理，并在 `final-independent-review.md` 和 `final-correction-report.md` 中保留证据。整改后重新执行相关数据库、后端、API、前端和浏览器测试，再生成最终 ZIP，并解压检查目录、文件、排除项和可启动性。

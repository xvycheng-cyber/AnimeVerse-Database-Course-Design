# 星漫云故障排查手册

## 1. 排查顺序

按以下顺序检查：

1. MySQL 是否运行。
2. `.env` 是否包含正确连接信息。
3. 数据库是否完成初始化。
4. 后端 8080 是否启动。
5. 前端 5173 是否启动。
6. 浏览器 Network 和控制台是否有错误。

先查看当前进程和端口：

```powershell
Get-Process | Where-Object { $_.ProcessName -match 'java|node|mysql' }
Get-NetTCPConnection -LocalPort 3306,8080,5173 -ErrorAction SilentlyContinue
```

## 2. MySQL 连接失败

### 症状

- 后端启动时报 `Communications link failure`。
- `test-database.ps1` 报 `mysqld` 或账户错误。
- 初始化脚本找不到 `mysql.exe`。

### 检查

```powershell
Get-Service | Where-Object Name -Match 'mysql'
Test-NetConnection 127.0.0.1 -Port 3306
```

确认 `.env` 的 `DB_HOST`、`DB_PORT`、`DB_USER`、`DB_PASSWORD` 正确。若 MySQL 客户端不在 PATH，可设置：

```powershell
$env:MYSQL_EXE='E:\mysql\install_directory\bin\mysql.exe'
```

不要通过修改其他数据库账户权限解决本项目连接问题。

## 3. 管理员初始化失败

### 3.1 管理员密码为空

在 `.env` 中填写 `MYSQL_ADMIN_PASSWORD`，或用执行进程环境变量提供。

### 3.2 数据库存在未知表

初始化脚本发现项目表之外的业务表时会停止。先确认这些表属于其他项目。不要直接使用 `DROP DATABASE`。如确需继续，应在备份和教师确认后单独处理。

### 3.3 应用账户权限

管理员执行：

```sql
SHOW GRANTS FOR 'Chengzi'@'localhost';
```

预期只包含目标库的 `SELECT, INSERT, UPDATE, DELETE, EXECUTE, SHOW VIEW`，以及全局 `USAGE`。应用账户不需要 `TRIGGER`，触发器由管理员安装。

## 4. Java 版本错误

### 症状

- 页面或日志显示 Java 21/26。
- 后端编译提示 release 17 不兼容。
- 启动脚本提示找不到 Java 17。

### 检查

```powershell
java -version
$env:JAVA_HOME
$env:JAVA_CMD
```

将 `JAVA_HOME` 指向 JDK 17，或设置：

```powershell
$env:JAVA_CMD='C:\path\to\jdk-17\bin\java.exe'
```

启动脚本会验证实际版本，不仅检查目录存在。

## 5. Maven 构建失败

先单独执行：

```powershell
cd .\backend
mvn clean test
```

常见原因：

- Maven 未找到：设置 `MAVEN_CMD`。
- 依赖下载失败：检查网络或本地 Maven 仓库。
- target 文件被占用：停止正在运行的后端，再执行 `clean package`。
- 测试数据库配置缺失：查看失败的测试类，不要跳过真实失败。

## 6. 后端 8080 启动失败

### 端口占用

```powershell
Get-NetTCPConnection -LocalPort 8080
Get-Process -Id (Get-NetTCPConnection -LocalPort 8080).OwningProcess
```

停止本项目旧进程，或修改 `.env` 的 `SERVER_PORT` 和 `VITE_API_BASE_URL`。不要结束不认识的系统进程。

### JWT 密钥过短

错误提示会说明 `JWT_SECRET` 至少 32 个 UTF-8 字节。重新生成随机字符串后重启。

### 环境变量缺失

确保 `.env` 包含 `DB_HOST`、`DB_PORT`、`DB_NAME`、`DB_USER`、`DB_PASSWORD` 和 `JWT_SECRET`。

## 7. 前端无法连接 API

### 症状

- 浏览器控制台出现 CORS。
- Network 请求 `net::ERR_CONNECTION_REFUSED`。
- 页面显示网络错误。

检查 `.env`：

```text
APP_CORS_ORIGIN=http://localhost:5173,http://127.0.0.1:5173
VITE_API_BASE_URL=http://localhost:8080/api
```

如果前端换端口，需要把新来源加入 `APP_CORS_ORIGIN`。修改后端 `.env` 后重启后端。

## 8. 登录后立即返回登录页

可能原因：

- JWT 已过期。
- 浏览器本地存储被清除。
- 后端 `JWT_SECRET` 已改变。
- API 返回 401。

退出并重新登录。仍失败时检查后端日志和浏览器 Network 中的 `/auth/login`、`/auth/me`。

## 9. 管理员菜单可见但接口 403

路由守卫和接口鉴权同时生效。确认登录账号包含 `ADMIN` 角色：

```sql
SELECT u.username, r.role_code
FROM sys_user u
JOIN sys_user_role ur ON ur.user_id = u.id
JOIN sys_role r ON r.id = ur.role_id
WHERE u.username = 'admin';
```

不要只修改前端菜单绕过权限。

## 10. 数据库测试失败

先执行完整测试，不要只重跑单个断言：

```powershell
.\scripts\test-database.ps1
```

如果失败项与事务审计有关，检查是否由失败的旧测试留下 `TRANSACTION_DEMO_*` 行。当前测试会在断言前清理三类事务演示标记。

如果触发器清单显示 0，确认是否使用应用账户查询 `information_schema.TRIGGERS`。应用账户没有 `TRIGGER` 权限时看不到触发器元数据，这是预期行为，行为测试仍应通过。

## 11. API 测试失败

确认：

- 后端已在 8080 启动。
- `admin` 和 `sakura` 种子账号存在。
- 数据库种子计数仍为 30 部动漫、8 家厂商。
- 前端和后端不是旧构建。

失败清理逻辑会尝试删除临时评论、类型和动漫。若进程被强制终止，使用数据库审计和测试脚本检查残留临时记录。

## 12. 浏览器测试失败

检查：

```powershell
Test-NetConnection 127.0.0.1 -Port 5173
Test-NetConnection 127.0.0.1 -Port 8080
```

脚本依赖 Puppeteer 和 Chrome。若 Chrome 路径不同，设置：

```powershell
$env:CHROME_PATH='C:\Program Files\Google\Chrome\Application\chrome.exe'
```

日志和 `docs/screenshots/browser-report.json` 会记录失败页面、HTTP 和布局问题。

## 13. 图片不显示

多数封面来自远程 AniList CDN。断网或 CDN 访问受限时，前端显示占位状态。动漫 ID 1 使用本地备用图，不会影响全部首页。

不要通过伪造远程图片成功来修改测试结果。若课程现场需要完全离线，应提前制作本地缓存并更新封面种子。

## 14. 删除操作失败

外键限制是预期保护。例如，已有收藏、评论、剧集或观看记录的作品不能直接删除。先查看依赖数据，不要通过关闭外键检查或删除父表绕过。

## 15. 事务异常模式“失败”

事务实验室的异常模式会故意返回 SQLSTATE 45000。页面应显示失败信息和回滚结果。这是正确行为，不是服务故障。

## 16. 构建大 chunk 警告

Vite 构建时报告 ECharts 或主包超过 500 kB。该警告不影响构建和运行，属于后续性能优化项。可进一步按路由拆分图表和后台页面。
